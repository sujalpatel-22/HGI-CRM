# HGI Billing: UI/UX, Android and QA audit (23 Oct 2026)

Scope: `src/app.template.html` (core app, ~2,950 lines), `src/mobile.js` / `mobile.css` (mobile shell), `src/i18n.js`, `src/demo-data.js`,
`native/` (Capacitor plugin), `tools/`, `tests/`, and CI. Baseline tests at the start of the audit: web 167/167 passed (4 viewports, plus upgrade checks);
Android emulator 28/28 on API 30/33/35/36 (CI run 16).

## Prioritized findings

### P0: data loss, wrong data or the user is blocked
| # | Finding | Where | Fix |
|---|---|---|---|
| 1 | **Setup wizard stuck on Bank & UPI.** A 10-character IFSC (e.g. `PUNB213800`) was rejected, but the error toast (z 60) sat *behind* the wizard (z 65), so nothing visible happened. *User-reported.* | `mobile.js` onboarding, `#toast-container` | ✅ Fixed: inline errors under each field, an 11-character IFSC rule with one-tap fix (`PUNB0213800`), the "name@bank" example rejected, toasts above every overlay |
| 2 | **Stale data can win after a restart.** The WebView localStorage quota (~5–10 MB, filled by logos and invoices) makes `saveState` fail silently on large books. The message also says "browser storage is blocked", which is wrong. | `saveState`, `restoreFromMirror` | ✅ Revision stamp on every save; start-up loads the newer copy; quota-specific warning; unreadable data kept as a recovery copy |
| 3 | **Restoring a backup replaces all data with no safety copy**, and the backup file is barely validated (only `company` is checked). | `importJSONBackup` | ✅ Structure validated; automatic pre-restore snapshot; **Undo restore** in Settings |
| 4 | **An invoice with an IRN can be edited** freely (items, totals, buyer, number), so the copy no longer matches the e-invoice registered on the IRP. | `saveCurrentInvoice` | ✅ Number/date/GSTIN/items/amounts locked; transport/PO/terms still editable |
| 5 | **Deleting an invoice with receipts, or with credit/debit notes against it,** loses the receipts and leaves the notes orphaned, which makes outstanding totals and GSTR-1 CDNR wrong. | `deleteInvoice` | ✅ Blocked with an explanation (also for IRN documents) |

### P2: UX (Phase 2 redesign)
- Lists (documents, items, buyers) render every table column as a label/value "spec sheet". One invoice card is ~400 px tall, so only 1–2 fit on a phone screen. Up to 9 action icons sit in an unlabeled grid.
- The header repeats "GST Billing & ERP System" on every screen and uses 2 lines for branding.
- Dashboard: KPI cards are large but visually flat; there are no quick actions; the alerts sit below the chart.
- Invoice editor: long form with no visual grouping of steps; field labels are tiny all-caps; the totals are only visible at the bottom.
- Inconsistent radii, shadows, button heights and colours across the core (Tailwind utilities) and the shell (mobile.css).
- Empty states are plain text.

### P3: security, performance and Android
- No Content-Security-Policy, though the app is fully offline and could use a strict one.
- `android:allowBackup` is the Capacitor default (true), and there are no backup rules. Google cloud backup copies the invoice database and PIN hash with no user control.
- The Chart.js chart re-renders on every dashboard visit (minor).
- WebView ≥ 80 is required (OK). Edge-to-edge and status bar were handled in v7.0.

### Not fixed in this pass (needs a product decision or backend)
- Multi-device sync, accounts and e-invoice API (Phase C–E in `UPGRADE-PLAN.md`).
- Stock is matched by item name, not by product ID, on invoices issued before this version (aliases mitigate this).
- The web build's client-side `admin/123` login (Android uses a PIN). Replacing it needs the server-side authentication planned in Phase C.

## Phases
1. **Critical bugs + GST/data accuracy:** items 1–10, with regression tests.
2. **UI/UX redesign:** a design-token layer (colour, type scale, radius, elevation, spacing), a compact header, a dashboard with quick actions, compact list rows with an overflow action sheet, a grouped invoice editor with a sticky totals bar, consistent buttons/inputs/chips, empty states, and dark mode. **The printed invoice is unchanged.**
3. **Security, performance and Android:** CSP, backup rules (data extraction rules for Android 12+), lazy chart, and accessibility (touch targets, labels, contrast).
4. **Regression + build:** web tests on 4 viewports and emulator tests on API 30/33/35/36; APK/AAB from CI (test key unless the owner key secrets are set).

## Phase 3 results
- **CSP** `default-src 'self'` (+ inline for the existing inline handlers); remote connections are blocked (tested). A side effect was found and fixed: the browser's speculative
  HTML scanner requested `${logo}`-style URLs from `<img src="${…}">` text inside the inline script. Invoice markup now builds its img tags as `<${IMG} …>` (output identical).
- **Backups:** Android cloud backup is excluded for app data (`dataExtractionRules` / `fullBackupContent`); Android 12+ phone-to-phone transfer is allowed;
  `usesCleartextTraffic=false`. CI fails the build if the rules are missing. PRIVACY.md updated.
- **Performance** (3,000 invoices, 1.2 MB, Chromium with 4× CPU throttle):

| | before | after |
|---|---|---|
| app start | 7.6 s | 1.3 s |
| open Documents | 4.0 s | 0.14 s |
| open Dashboard | 1.3 s | 0.17 s |

  Cause: `notesAgainst()` scanned every document for every row (O(n²)). It is now indexed per data revision, and the register renders 150 rows at a time with "Show more" (totals still cover all rows).
- **Accessibility:** icon-only buttons get aria-labels; visible focus ring; reduced-motion support; 48 px inputs on phones.
- **Fixed during testing:** restoring a backup that had no `onboarded` flag reopened the setup wizard over the app.
